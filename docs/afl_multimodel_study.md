# Repeated Multi-Model AFL++ Seed Study

This study tests whether initial seed sets generated by multiple local LLMs change AFL++ outcomes for the free5GC 5GMM and 5GSM parsers. It must report all cells and paired repetitions; do not choose models, seeds, repetitions, or metrics after seeing outcomes to force a positive conclusion.

## Design

- Models: local models recorded in `matrix_manifest.json` (default: `llama3.2:3b`, `qwen2.5-coder:3b`).
- Targets: `ParseGMM` and `ParseGSM`, invoked by the file-input Go adapter and AFL++ QEMU mode.
- Arms: ordinary protocol-template seeds versus model-generated seeds; equal seed counts per parser.
- Repetitions: default three paired repetitions per model/parser. Each ordinary/LLM pair uses the same AFL RNG seed, target binary, runtime, timeout, memory limit, and process environment.
- Run order: randomized model/parser pair order; baseline-first versus LLM-first alternates by repetition.
- Primary exploratory metric: paired change in `corpus_found` and QEMU bitmap coverage. Also report executions, map edges, stability, timeouts, crashes and hangs for every run.

Three repetitions constitute a pilot, not a statistically conclusive evaluation. Increase repeats and run duration for paper claims, use predeclared metrics, report paired distributions and uncertainty, and retain negative/neutral outcomes. AFL++ QEMU stability was around 90% in previous Go runs and warnings were emitted, so coverage-derived effects are provisional until that instrumentation issue is addressed.

## Prepare corpora

Start local Ollama and verify both selected models are available. Seed generation contacts only `127.0.0.1`:

```bash
cd /home/msai/qinh0007/free5gc-security-lab
PYTHONPATH=src /home/msai/qinh0007/nwdaf-research/.venv/bin/python \
  scripts/afl_seed_comparison.py prepare-matrix \
  --campaign data/results/afl_multimodel_20261002_v1 \
  --models llama3.2:3b,qwen2.5-coder:3b \
  --count 4 --repeats 3 --seed 20261002 \
  --ollama-url http://127.0.0.1:11434
```

The preparation step validates unique hex byte strings, removes within-arm duplicates, records cross-arm overlaps and seed hashes, and fails before writing if a model cannot produce the requested count. It never fills the LLM arm with ordinary seeds.

## Run on Slurm

The matrix contains 24 sequential AFL++ runs at 60 seconds each, plus QEMU/Go startup and calibration. Submit it to the cluster rather than running the full matrix on a shared login node:

```bash
campaign=/home/msai/qinh0007/free5gc-security-lab/data/results/afl_multimodel_20261002_v1
mkdir -p "$campaign/logs"
sbatch --time=02:00:00 --cpus-per-task=1 --mem=4G \
  --output="$campaign/logs/slurm-%j.out" \
  /home/msai/qinh0007/free5gc-security-lab/scripts/run_afl_matrix_slurm.sh "$campaign"
```

The job writes `matrix_results.csv`, `matrix_results.json`, `paired_deltas.csv`, and `matrix_report.md`, plus a separate raw `fuzzer_stats` file for each run. Keep the experiment output in its new campaign directory; do not overwrite the curated-seed or v3 comparison runs.

## Caveats

The host routes core dumps through an external handler, so the runner enables `AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1`; crash reporting may be delayed or unreliable. The adapter is parser-only and has no network/testbed side effects. This experiment does not replay findings, collect Linux/SBI/PFCP telemetry, evaluate NWDAF detection, or apply mitigation.
